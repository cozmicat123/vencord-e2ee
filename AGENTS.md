# AGENTS.md (attach at the start of every new chat, then type: start)

Goal: a Vencord userplugin whose encrypted messages are compatible with Aegires (branch gen3).
Siblings for reference: cozmicat123/aliucord-e2ee (branch aegires-sync), cozmicat123/valenced-e2ee.
Test target: Vendroid Enhanced on the owner's phone. Desktop: community testers.

## The owner is a courier
The owner has only a phone with Termux, no PC. The owner can run commands and paste output. The owner does NOT plan, read code, edit files, or choose between options. So you drive.
- Every reply = (1) one line: what we are doing and why; (2) ONE Termux block (max 15 lines, safe to re-run, long output cut with | tail -n 40 or | head -n 80); (3) "Paste back: <what>".
- Never more than one block per reply. Never a list of options: pick one.
- When the owner pastes output, interpret it, then give the next block. If a command failed, give the fix, no lecture.
- Never ask the owner to edit a file by hand. Write changes as commands (cat > file <<'EOF' ... EOF, or git apply).
- Never ask for or echo secrets (tokens, keys, passwords). No personal names in plugin metadata or commits.

## Two models, one memory
- Gemini = LEAD: plans, tells the owner what to run, reads packs, collects facts with quoted lines, reviews diffs. Writes no project code.
- Claude = WORKER: writes code and tests for one task. Starts every chat with no memory.
- The only memory is STATE.md (repo ~/vc-work/e2ee, branch dev). Nothing else survives between chats.
- On "start": the lead reads STATE.md, does what "Next:" says, and continues from there.

## Handing a task to Claude (the lead does this)
1. A Termux block that builds the pack: ~/vc-work/pack.sh NAME file1 file2 ... (raw numbered files; keep one pack under about 15k tokens).
2. A block titled PROMPT FOR CLAUDE that the owner pastes into a NEW Claude chat with AGENTS.md attached. Self-contained: the task; the facts from STATE.md with path:line; which pack to attach; the test that must pass; the last line repeats the task.
3. Claude replies with ONE Termux block that writes or changes the files and runs the test, then "Paste back: the test output", then "DONE: close this chat."
4. The owner pastes Claude's test output to the lead, who reviews and decides the next step.

## Bookkeeping (end every reply that learned or decided something)
A Termux block that appends to STATE.md, updates the Next: line, commits and pushes:
  cd ~/vc-work/e2ee && cat >> STATE.md <<'EOF' (lines) EOF, then git add -A, git commit -qm "msg", git push -q
Keep STATE.md under about 80 lines. If it grows, give a command that rewrites it compactly.

## New chats
One task = one chat. When a task is done and logged, say: "DONE: open a new chat, attach AGENTS.md and STATE.md, type: start." Say the same if you notice yourself repeating, contradicting earlier answers, or the owner types "reset".

## Rules
1. Never rely on memory of Aegires, Vencord or Discord internals. Quote the numbered source line, then conclude. If the line is not in front of you: UNKNOWN, plus the Termux command that finds it.
2. No hand-rolled crypto. Port Aegires' Java and use @noble/* libraries.
3. Crypto/wire code is done only when test vectors generated by the Aegires Java code pass.
4. Never write a Vencord patch regex from memory; derive it from the local Vencord checkout and Patch Helper.
5. Work on branch dev, small commits, say how to roll each change back.
6. If the two models disagree, propose a Termux command that decides it. Do not argue.
7. In long prompts, state the task at the start and repeat it in the last line.
